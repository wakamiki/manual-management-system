## 1. プロジェクト概要

### 1-1. システム名

業務マニュアル管理システム
(Manual Management System)

### 1-2. 開発目的

本システムは、現場で日々更新される業務知識を一元管理し、
業務知識の属人化防止・標準化・共有効率向上を目的とした
業務ナレッジ共有システムである。

### 1-3. 想定利用者

* 一般利用者（USER）
* 承認者（APPROVER）
* 管理者（ADMIN）

### 1-4. 開発背景

業務現場では、日々の運用変更や例外対応が
口頭・個人メモ・チャットで共有されることが多く、
以下の課題が発生しやすい。 

* 業務知識の属人化
* 最新版マニュアルが分からない
* 更新履歴が追えない
* 承認済み / 未承認情報の区別が難しい
* 引継ぎ時の情報欠落
* 「言った・聞いていない」問題

## 2. 解決したい業務課題

### 2-1. 現場課題

* 業務手順の属人化
* 更新履歴の追跡困難
* 情報の鮮度が分からない
* 口頭共有による認識齟齬
* 教育コスト増大

### 2-2. システムによる解決方針

* 承認状態の可視化
* 更新履歴保持
* 旧版管理

* 検索性向上

## 5. 技術構成

### 5-1. 使用技術

* Java 17
* Spring Boot
* Spring Data JPA
* Thymeleaf
* Bootstrap
* H2 Database
* PostgreSQL / Supabase
* Git / GitHub

### 5-2. 技術選定理由（概要）

#### Spring Boot

業務システム開発で実務利用が多く、
MVC・Service・Repository の責務分離を学べるため。

#### Bootstrap

短期間で見やすい業務画面を構築しやすく、
レスポンシブ対応しやすいため。

#### PostgreSQL / Supabase

公開環境を想定した永続DBとして拡張性が高いため。

#### Render

ポートフォリオ公開を想定し、
Webアプリとして面接で見せやすいため。

### 9-3. 保守性を意識したEntity設計

業務状態に関わる項目（status / role / isActive / 時間系）は
単純setterを使用せず、専用メソッドによる更新制御を採用する。

例

* markCreatedNow()
* markUpdatedNow()
* markApprovedNow()

これにより、不正な状態更新や日時不整合を防止し、
チーム開発におけるレビュー性・保守性を向上させる。
