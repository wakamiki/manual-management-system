```text
ログイン画面
  -> トップ画面
     -> マイページ
     -> マニュアル詳細画面
     -> マニュアル入力画面（編集 / 複製）
```

- `詳細を見る` は別タブで開く

- `新規作成` は新規作成専用画面を別タブ表示する
- 管理画面は親画面を閉じずに作業できるよう別タブで開く

### 4-1. 表示内容
- 検索フォーム
- カテゴリ絞り込みフィルタ
- ステータス絞り込みフィルタ(PENDING/APPROVED/ARCHIVED)
- 新規作成ボタン
- ホームアイコン
- ログイン中ユーザー名
- 通知バッヂ
- クイックビュー
- カテゴリ一覧
- 使用停止中カテゴリ
- マニュアル一覧
- ページネーション
- 一覧には以下を常時表示する
  - マニュアルID
  - タイトル
  - ステータス
  - 更新日
  - 作成者
  - カテゴリ
- アコーディオン展開時に以下を表示する
  - コンテンツ
  - 更新履歴

### 4-2. ホームアイコン
- 左下に配置する
- クリックでマイページへ遷移する
- Bootstrap Icons の `house-fill` を使う
- アイコンの右側にログイン中ユーザー名を表示する

### 4-3. 通知バッヂ
- 上段: 差し戻し通知件数
- 下段: 未承認通知件数
- 差し戻しはオレンジ
- 未承認は緑

### 4-4. 一覧操作
- 詳細を見る
- 編集
- 複製

### 4-5. 検索条件
- カテゴリはコンパクトなドロップダウン内で複数選択できる
- ステータスはコンパクトなドロップダウン内で複数選択できる
- アーカイブ検索は独立チェックボックスではなく、ステータス絞り込みに含める
- カテゴリ選択肢は 有効なカテゴリを表示 とする
- ステータス選択肢は `申請中 / 承認済 / アーカイブ` とする
- 複数項目を同時にチェックして一括検索できる
- 初期表示では `申請中 / 承認済` を選択済みにし、`アーカイブ` は未選択とする
- 使用停止カテゴリはカテゴリフィルタ内で `使用停止中` のミニ開閉にまとめる
- 検索フォーム送信は `GET /manuals/index` とする
- 検索条件は以下の name で送る
  - `keyword`
  - `categoryIds`（複数）
  - `statuses`（複数）
- 検索後は keyword/category/statuses の選択状態を保持する

### 4-5A. Thymeleaf 連携ルール（index）
- 一覧表示の参照起点は `listDto` とする
  - `listDto.searchManuals`
  - `listDto.activeCategories`
  - `listDto.inactiveCategories`
  - `listDto.summaryDto`
- 検索条件表示の参照起点は `manualSearchConditionDto` とする
  - `manualSearchConditionDto.keyword`
  - `manualSearchConditionDto.categoryIds`
  - `manualSearchConditionDto.statuses`
- `th:each` は「1データ = 1 UI ブロック」に付与する
  - マニュアル一覧は `accordion-item` 単位
  - カテゴリ一覧は 1カテゴリ1行単位

### 4-5B. アコーディオン実装ルール
- 行ごとにユニークな id を使う
  - 例: `collapse-${stat.index}`
- `id` / `data-bs-target` / `aria-controls` は必ず一致させる
- 初期閉で表示する場合は以下を明示する
  - `accordion-button collapsed`
  - `aria-expanded="false"`
  - `accordion-collapse collapse`

### 4-6. 左サイドバー
- 左サイドバーは検索条件入力ではなく、クイックビューと補助ナビゲーションとして扱う
- クイックビューには以下を表示する
  - 自分の作成分
  - 申請中
  - 最近更新
- 各クイックビュー項目には件数を表示してよい
- カテゴリ一覧はサイドバー下段の補助ナビとして残す
- 使用停止中カテゴリはサイドバー内でも折りたたみ表示とする
- サイドバーは補助ナビ用途とし、検索条件の主入力は上部検索フォームで行う

### 4-6A. クイックビュー（最近更新）
- 最近更新: 直近7日以内に更新されたマニュアル件数を表示
- 判定条件: `updatedAt >= 今日 - 7日`
- 表示例: `最近更新 5`

### 4-6B. 検索フォーム
- カテゴリ: 複数選択対応
- ステータス: 複数選択対応
- 検索後も選択状態を保持する
- Thymeleaf で現在値を再表示する

## 5. SCR-003 マニュアル詳細画面

### 5-1. 表示内容
- マニュアルID
- タイトル
- カテゴリ名
- ステータス
- 作成日
- 更新日時
- 作成者名
- 本文
- 更新履歴
- 履歴日時
- 更新履歴（内部項目名: changeNote）
- 更新者名

### 5-2. 更新履歴表示
- 各履歴行には `履歴日時 / 更新者名 / チェンジノート` を表示する
- 更新者名は更新履歴の各行で確認できるようにする

### 5-3. 日時表示ルール
- 作成日は日付中心で表示する
- 更新日時は時間まで表示する

### 5-4. ボタン表示
- 編集（作成者専用）
- 複製
- マニュアル公開（作成者専用）
- 承認（承認者/管理者専用）
- 差し戻し（承認者/管理者専用）
- アーカイブ（承認者/管理者専用）
- 復帰（承認者/管理者専用）

### 5-5. 補足
- 差し戻し / アーカイブ / 復帰は詳細画面でインライン入力した `changeNote` を使って確定する
- 差し戻し / アーカイブ / 復帰のインライン入力パネルは共通UIとし、操作名と確定ボタン文言だけ切り替えてよい
- 画面上の入力ラベルは `changeNote` ではなく `更新履歴` と表示してよい
- 承認はボタン押下時に `履歴コメントを残しますか` の確認ダイアログを表示してよい
- 承認ダイアログで `はい` を選んだ場合は詳細画面でインライン入力を開き、コメント付き承認とする
- 承認ダイアログで `いいえ` を選んだ場合はコメントなしで承認してよい
- 復帰対象は承認日時を持つアーカイブ済マニュアルとする
- GUEST 操作時は更新系ボタンを非活性表示し、`ログインすると利用できます` または `権限不足` を表示する

## 6. SCR-004 マニュアル入力画面（編集 / 複製）

### 6-1. 画面名
- `manual-form`

### 6-2. モード
- 編集
- 複製

### 6-3. 入力項目
- manualId
- title
- content
- category
- changeNote
- updatedAt
- createdAt
- createdByUser

### 6-3A. モード切替情報
- mode: `edit` / `copy`
- モードバッジ文言を切り替える
- submit 先 URL と保存ボタン文言を mode で切り替える
- `copy` は changeNote 必須、`edit` は任意（業務ルールによる）
- mode は同一画面内の表示文脈として扱い、保存処理は mode ごとの専用エンドポイントで受ける
- 編集モードと複製モードは、同じ `manual-form` を使いながら別ユースケースとして扱う

### 6-4. ボタン
- 下書きに保存
- マニュアル公開

### 6-5. 補足
- 見た目は旧編集画面をベースに統一する
- 編集 / 複製モードでは `マニュアルID / 作成日時 / 更新日時 / 作成者` を表示する
- 入力画面内には複製ボタンを置かない
- `下書きに保存` では `PENDING → DRAFT` を許可する
- 差し戻し / アーカイブ / 復帰は `manual-form` ではなく詳細画面のインライン入力で扱う

## 8. SCR-006 ユーザー管理画面
- ユーザー登録 / 更新フォーム
- ユーザー一覧
- ページ切り替え
- role / status / lastLoginAt の表示
- 停止 / 復帰 / パスワードリセット操作
- 画面モードを `CREATE` / `EDIT` で切り替える
- 初期表示は `CREATE` モードとする
- 一覧の設定操作で `EDIT` モードへ切り替える
- 新規作成時は初期状態をアクティブとする
- 入力必須: userId / displayName / role
- 更新時も userId は変更可とする
- パスワードリセットは ADMIN のみ実行可（アクティブユーザーのみ）
- 自分自身のリセットは禁止
- 一時パスは通知で渡す
- 初回ログインで強制パスワード変更
- 監査ログを記録（操作者・対象・日時・理由）
- 連続実行は制限する
- 一覧の設定ボタンは `GET /users/{userId}/action` を呼び出し、更新モードへ切り替える
- 新規作成/更新/停止/復帰/パスワードリセットは `POST` 送信で実行する
- フォームは `th:object="${formDto}"` を使用し、入力項目は `th:field="*{...}"` でバインドする
- モード切替時に `targetUser` が null の場合は更新系ボタンを表示しない

## 10. SCR-008 マイページ

### 9-1. 画面コンセプト
- 個人向けダッシュボード
- 通知タブ仕様は未確定

### 9-2. タブ（暫定）
- 通知（未確定）
- 作成マニュアル
- 未承認マニュアル

### 9-3. 表示ルール
- USER
  - 通知
  - 作成マニュアル
- APPROVER / ADMIN
  - 通知
  - 作成マニュアル
  - 未承認マニュアル

### 9-4. 通知サマリー
- ホームアイコンのプレビューを表示する
- 上段に差し戻し件数
- 下段に未承認件数

### 9-4A. 一覧表示方針
- 通知件数は未読のみを対象とする
- 一覧は状態条件で全件表示する
  - 差し戻し一覧: `isRolledBack = true`
  - 承認待ち一覧: `status = PENDING` かつ `createdByUser != current user`

### 9-4B. 既読操作
- 通知は一覧表示だけで既読化しない
- 既読ボタンで明示的に既読化する

### 9-5. 将来拡張
- お気に入りマニュアル表示を追加予定

### 9-6. 取得方式
- 初回表示時に必要データをすべて取得する
- タブ切り替えは画面内表示切替のみとし、再リクエストは行わない

## 11. SCR-009 パスワード変更画面
- 対象: 初回ログインユーザー、またはパスワード変更導線から遷移したユーザー
- 入力項目
  - currentPassword
  - newPassword
  - confirmPassword
- 入力ルール
  - 文字数: 8〜32文字
  - 文字種: 大文字・小文字・数字を各1文字以上含む
  - 許可文字: `A-Za-z0-9!@#$%^&*()_-+=`
- エラー表示
  - 必須未入力
  - 新規/確認パスワード不一致
  - 形式不正（文字数/文字種/許可文字）

## 12. 画面エラー切り分けメモ（運用）
- `EL1007E ... cannot be found on null` はテンプレート記法より先に `model.addAttribute` と DTO 中身を確認する
- `/manuals/index` と `/` で再現差がある場合はルーティング設定起因を疑う
- 表示件数 0 は `th:each` 不具合ではなく、検索初期条件（status）で除外されている可能性を先に確認する
- 405 発生時は `a(th:href)` が GET、`button(type=submit + th:formaction)` が POST である点を先に確認する
- `Property or field ... cannot be found on null` 発生時は、まず `target... != null` 条件で表示ブロックをガードする
