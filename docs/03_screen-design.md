## 2. 画面遷移図

### 2-1. 全体遷移

```text
ログイン画面
  ↓
トップ画面
  ├→ マニュアル詳細画面（別タブ）
  │     ├→ マニュアル編集画面（別タブ）
  │     └→ マニュアル新規作成画面［複製モード］（別タブ）
  ├→ マニュアル新規作成画面（別タブ）
  ├→ ユーザー管理画面（別タブ）
  └→ カテゴリ管理画面（別タブ）
```

### 2-2. 条件付き遷移

* 一覧項目クリック時は同一画面内でアコーディオン展開する
* `詳細を見る` 押下時はマニュアル詳細画面を別タブで開く
* `編集` 押下時はマニュアル編集画面を別タブで開く
* `複製` 押下時はマニュアル新規作成画面を複製モードで別タブ表示する
* `新規作成` 押下時はマニュアル新規作成画面を別タブで開く
* `ユーザー管理` / `カテゴリ管理` は権限に応じて別タブ遷移可否を制御する

### 2-3. 別タブ運用ポリシー

* トップ画面は検索 / 絞り込み / 起点となる親画面として扱う
* マニュアル詳細画面は、検索中に複数マニュアルを突き合わせて参照できるよう別タブで開く
* 新規作成 / 複製 / 編集は入力専用の独立タブとして扱う
* 管理画面も業務画面を閉じずに参照・更新できるよう別タブで開く
* 別タブ画面の終了導線は `戻る` ではなく `閉じる` を基本とする

### 2-4. 状態別ボタン表示方針（概要）

* DRAFT は `編集 / 申請 / 複製 / アーカイブ` を基本表示とする
* PENDING は `承認 / 差し戻し / アーカイブ / 複製` を基本表示とする
* APPROVED は `複製 / アーカイブ` を基本表示とする
* ARCHIVED は `複製 / 復帰` を基本表示とする
* USER は作成 / 編集 / 申請を中心とし、承認系ボタンは表示しない
* APPROVER は承認 / 差し戻し / アーカイブ / 復帰を中心とする
* ADMIN は APPROVER 権限に加え、管理画面遷移を持つ
* 作成者本人による承認は禁止し、必要に応じて disabled 表示で理由を伝える

## 6. 新規作成画面 / 複製画面（SCR-004）

### 6-1. 画面位置づけ

* 入力専用の独立画面
* トップ画面 / 詳細画面とは別タブで開く前提
* 既存マニュアルを参照しながら入力できる運用を想定する

### 6-2. 表示項目

* modeLabel（新規作成 / 複製）
* sourceManualSummary（複製時のみ）
* title
* content
* category
* changeNote

### 6-3. 入力項目

* title
* content
* categoryId
* changeNote

### 6-4. ボタン一覧

* 下書き保存
* 確認して申請
* 閉じる

### 6-5. 複製モード初期値

* title は複製元の値を初期表示
* content は複製元の値を初期表示
* category は複製先カテゴリを再選択可能
* changeNote は空欄で初期表示し必須入力
* currentStatus は表示しないが保存時は DRAFT 扱い

### 6-6. sourceManualSummary 表示項目

* 複製元タイトル
* 複製元カテゴリ
* 複製元ステータス
* 複製元更新日

### 6-7. バリデーション表示

* 必須
* 最大文字数
* エラーメッセージ
* 複製元カテゴリ停止時
* changeNote 必須

### 6-8. 終了導線

* `閉じる` は入力用別タブを閉じる操作として扱う
* `戻る` は使わない
* 保存成功後の業務遷移は詳細設計書に従う

## 10. 共通 UI 仕様

### 10-1. メッセージ表示

* 簡潔な成功メッセージ
* エラーメッセージ
* 警告メッセージ

### 10-2. 画面別役割

* トップ画面：検索 / 絞り込み / 画面起点
* 詳細画面：参照 / 比較用
* 新規作成 / 複製 / 編集：入力用
* 管理画面：管理用

### 10-3. レスポンシブ方針

* PC 前提の 2 カラム構成
* サイドバーとメインを並列表示
* スマホ最適化は主目的にしない

### 10-4. 共通デザイン方針

* Bootstrap ベース
* disabled 理由を表示
* 業務利用を優先した視認性重視
* コンパクトで一覧性を保つ

---

## 11. 注意点

* モック段階では別タブ遷移を `a` タグ + `target="_blank"` で表現してよい
* 画面右上の `閉じる` は、別タブ運用を表現する UI として扱う
* ブラウザ制御の実装は Thymeleaf 化 / バックエンド連携後に検討する
